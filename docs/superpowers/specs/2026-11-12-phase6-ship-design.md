# Phase 6 Ship It — Design

Status: approved in brainstorming 2026-11-12, section by section. Base: `main` at `689dba9` (Phase 5 merged, PR #5). Branch: `phase6-ship`.

## 1. Intent

Make the tracker presentable and durable, without changing what it does:
- **A public home:** the code in a **new public GitHub repo** with a rewritten history, under MIT; this repo stays private and is archived.
- **A public demo:** a static **snapshot** of the map and `/history` on GitHub Pages, generated by one offline command and pushed by hand after a review. It is a portfolio demo, stamped "Snapshot of <date>, not live", never a live tracker.
- **A README for a visitor:** what it does, architecture, evals as measured (including the failed street gate), screenshots, how to run, start-at-login, licences.
- **`serve` that survives reboots and sleep:** a Task Scheduler install script (logon task + optional wake task) and a single-instance lock.

Success:
- Nothing private reaches the public repo or the snapshot: no subscriber data, chat IDs, token, work email, the owner's barangay, or whole VECO posts, in the tree **or in any reachable commit**.
- `snapshot` is offline, read-only, and refuses to publish old data by accident.
- The snapshot page behaves like the local map for the stored weeks, with time pinned to the snapshot, in Manila time.
- Two `serve` processes can never run against the same DB.

## 3. Findings that shaped the design

- **Pages on a free plan needs a public repo**; this repo is private (`gh repo view`: `PRIVATE`). The plan type couldn't be read; free was assumed and the owner chose to go public.
- **What the old history exposes:** the author email on 95 of 100 commits is the owner's work address; `ROADMAP.md` names the owner's own subscribed barangay (Phase 5 treats a barangay as close to a home address); `tests/fixtures/posts/` holds 12 whole VECO pages, 17 MB, mostly Wix boilerplate, in every commit since Phase 1. Neither email appears in any tracked file or commit message; no `.env`, DB or `data/` file was ever committed; no chat ID is in any tracked file. The OSM fixtures are synthetic.
- **The pages already use relative URLs** (`outages.geojson`, `stats.json`, `boundaries.geojson`, `static/…`, `history`, `./`), so they work from a folder under a subpath.
- **Two things still need a server:** the map reads `Date.now()` for the default day/hour, the 15 h old-data warning and the refetch timer; `/history` computes any range on request.
- **Sizes (real DB, read-only, hash unchanged):** 53 weekly documents = 8.3 MB, of which ~7 MB is the same boundary geometry repeated; the outages alone 1.2 MB (1,217 outages, 125 K chars of `areas_raw`); the 12-month stats 28 KB; `boundaries.geojson` 135 KB.
- **`serve` has no single-instance guard**, and the owner sometimes starts it in a terminal; a login task plus a terminal run would mean two schedulers (double VECO fetches, a race on the alert ledger) and two Telegram pollers (409).
- **Under `pythonw` (no console) `sys.stderr` is `None`:** the console log handler would fail on every record. The file log (`data/logs/outages.log`, 5 × 1 MB) is unaffected.
- **Sleep, not only reboots, misses runs:** a suspended process resumes on wake and APScheduler runs a missed job only within the 6 h grace, so a 20:00 run slept through until 07:00 is skipped.

### 4.1 `snapshot` command

`python -m outages snapshot --out <dir> [--allow-old]`

- **Offline and read-only:** opens the DB with `db.connect_ro`; never builds the VECO fetcher, the Overpass client or a Telegram client (tested). Does not take the lock.
- **Pinned time:** `taken_at` = now in Manila, seconds precision, used for every window, range and label.
- **Freshness:** if `last_check_at` is missing or more than `STALE_CHECK_H` (15) hours before `taken_at`, exit 2 with "data is N h old; run check first or pass --allow-old". With `--allow-old` it proceeds and the page shows the old-data warning (§4.3).
- **Output folder rules:** `<dir>` may be missing, empty (a `.git` *file*, the worktree link, counts as empty), or hold a previous snapshot (has `snapshot.json`). Anything else → exit 2, nothing written. On refresh, files under `weeks/` and `stats/` not in the new set are deleted; `.git` is never touched.
- **Build in memory, then write:** every document is built first (~9 MB); any exception → exit 1, nothing written. Files are written UTF-8 with `dumps()` (the server's serializer, so output is byte-stable for unchanged data).
- **Prints** a summary: taken_at, last_check_at, weeks written/removed, ranges, total bytes.

**Windows:**
- The snapshot week: `default_window(conn, taken_at)` (today to the last stored end, ≤ 7 days), file `weeks/<taken_date>.geojson`.
- Past weeks k = 1…52: `from = taken_date − 7k`, 7 days, file `weeks/<from>.geojson`. They tile with the snapshot week: no gaps, no overlaps.
- Each file = `build(conn, gaz, boundaries, window, taken_at)`, unchanged format.

**Ranges** (`stats/<id>.json` = `compute(...)` with `now = taken_at`):

| id | label | from | to |
|---|---|---|---|
| `last-12-months` | Last 12 months | taken_date − 364 | taken_date |
| `2024` | 2024 | 2024-01-01 | 2024-12-31 |
| `2025` | 2025 | 2025-01-01 | 2025-12-31 |
| `<current year>` | `<year>` to date | Jan 1 of taken year | taken_date |

Calendar years from 2024 (the archive's start) to the taken year; the default is `last-12-months`.

**Layout:**
```
<out>/
  index.html, history.html      copied from static/, <html data-mode="snapshot">
  static/                       css, js, vendor (copied unchanged)
  snapshot.json
  boundaries.geojson
  weeks/<from>.geojson          53 files
  stats/<id>.json
  LICENSES.md                   data and licence notes (§4.6)
  .nojekyll
```

**`snapshot.json`:**
```json
{
  "format": 1,
  "taken_at": "2026-11-12T20:05:11+08:00",
  "last_check_at": "2026-11-12T20:00:42+08:00",

  "weeks": ["2025-11-13", "2025-11-20", "…", "2026-11-05", "2026-11-12"],
```

### 4.2 What goes public, and how that is enforced

- **In:** exactly what the local map and `/history` already serve: outage times, status, purpose, `areas_raw`, the post's URL and title, barangays, entities, streets (in words while drawing is off), `meta`, stats. These are VECO's public schedule facts; every outage links back to its post. No whole post text is copied (the parsed fields only).
- **Never:** subscribers, subscriptions, the alert ledger, bot state, chat IDs, logs, `.env`, `data/osm/`.
- **Authorizer:** the snapshot's connection installs `sqlite3.set_authorizer` that denies `SQLITE_READ` on `subscribers`, `subscriptions`, `alerts_sent` and every other bot/alert table (the list comes from the schema, by name prefix + explicit names, and a test fails if a new table appears unclassified).
- **Leak scan:** after building and before writing, the output bytes are scanned for every stored chat ID and for the `TELEGRAM_BOT_TOKEN` value if `.env` has one; a hit → exit 1, nothing written, and the message names the kind ("chat ID", "bot token") never the value.

### 4.3 Pages in snapshot mode

`source.js` exports `makeSource(mode, meta)` with `weekUrl(from)`, `statsUrl(rangeId)`, `now()`, and `weeks`/`ranges`. Live mode keeps today's URLs and `Date.now()`. `map.js` and `history.js` get every URL and every "now" from it, never from `Date.now()` directly (a test greps for it).

**Map (`index.html`):**
- Loads `snapshot.json`, then `weeks/<snapshot_week>.geojson`; default day/hour = `defaultSelection(taken_at, days)`.
- **Banner** (replaces the history banner in this mode): "Snapshot of Thu 12 Nov 2026, 20:05 (Manila), not live. For current schedules see VECO's advisories." with the VECO link.
- **Old-data warning** = `checkAgeHours(last_check_at, taken_at) > 15`.
- **Week picker:** ◀ ▶ step through `weeks` and disable at the ends; the date input has `min`/`max` and snaps to the stored week containing the date; **Today** → the snapshot week. A past week shows "History: …" as now.
- **No refetch timer** and no `visibilitychange` refetch.
- **Missing week file** (404 or bad JSON) → banner "This week isn't in the snapshot", back to the snapshot week.

**History (`history.html`):** the From/To form is replaced by a `<select>` of `ranges` (default `default_range`); the URL keeps `?range=<id>`. Everything else is unchanged.

**Both pages:**
- Tiles from `tiles.js` (one URL, `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, attribution visible on the map). The credits gain "Report a map issue" → `https://www.openstreetmap.org/fixthemap`.
- No `Referrer-Policy` meta tag, no prefetch.
- Footer in snapshot mode: "Snapshot of …; code: <repo link>; licences: LICENSES.md".

### 4.4 Single instance (`lock.py`)

- `acquire(path) -> Lock | None`: opens `data/serve.lock`, takes an exclusive non-blocking OS lock (`msvcrt.locking(fd, LK_NBLCK, 1)` on Windows, `fcntl.flock(LOCK_EX | LOCK_NB)` elsewhere), writes the PID; held for the life of the process, released on exit or crash by the OS.
- **Taken by:** `serve`, `bot`, `alerts --send`, `check`, `backfill`. A second one exits **3**: "serve is already running (pid N); stop it first" (the PID read from the file; "unknown" if unreadable).
- **Never taken by** read-only commands (`map`, `report`, `stats`, `snapshot`, `alerts --dry-run`, `streets --review`, `eval`, …).
- **No OS lock available** (neither module): log a warning and run.

### 4.5 Logging without a console

`_setup_logging` adds the console handler only when `sys.stderr` is not `None`; the rotating file handler always. `print` to a `None` stdout is already a no-op.

### 4.7 Fixture trimming

Each `tests/fixtures/posts/*.html` is replaced by a minimal HTML document holding only the node the parser reads (the post's content cell) and whatever the parser uses outside it (title, `<link rel=canonical>`/metadata it reads, if any), with no `<script>`, `<style>` or Wix boilerplate. Rule: **every golden output stays byte-identical** and every text hash the tests compute is unchanged; each file < 200 KB. The trimming is a pure function in `scripts/trim_fixture.py` (committed, so the public repo shows how its fixtures were made, and so the history rewrite in §4.8 applies the same function to every historical version).

### 4.11 Start-at-login (`scripts/install-task.ps1`)

Run by the owner from the project root; the build only parses it and runs `-WhatIf`.
- **"OutageTracker serve":** trigger at logon of the current user; action `.venv\Scripts\pythonw.exe -m outages serve`, working directory the project root; settings: no execution time limit, restart on failure 3 × 1 min, start when available, run on battery, multiple instances `IgnoreNew`.
- **"OutageTracker wake"** (unless `-NoWake`): daily 05:58 and 19:58, "Wake the computer to run this task", action `cmd.exe /c exit 0`.
- `-Uninstall` removes both; `-WhatIf` prints what it would register.
- If registering a logon trigger needs an elevated shell, the script says so and exits 1; the README says to run it as administrator then.
- README: turn on "Allow wake timers" in the power plan yourself; restart after an update = `git pull` → `pip install -e .` → `Stop-ScheduledTask "OutageTracker serve"` → `Start-ScheduledTask "OutageTracker serve"` (a stop mid-run is safe for the DB; at worst one alert repeats, consistent with the ledger rule); "data more than 15 h old" checklist: the task's Last Run Result, the tail of `data/logs/outages.log`, whether the PC slept past the 6 h grace.

| Situation | Behaviour |
|---|---|
| DB missing, not migrated, areas not run | `snapshot` exit 2 with the map's existing messages |
| Data older than 15 h | `snapshot` exit 2 unless `--allow-old` |
| `--out` holds foreign files | exit 2, nothing written |
| Any exception while building | exit 1, nothing written |
| Leak scan hit | exit 1, nothing written; message names the kind only |
| Lock held | exit 3 with the PID |
| No OS lock module | warning, run |
| No console (`pythonw`) | file log only |
| Week file missing on the page | banner, back to the snapshot week |
| Tiles blocked or withdrawn | polygons on a blank background (existing `tileerror` handling) |

## 12. Risks and accepted limits

- **OSM may withdraw tile access** without notice; the demo then shows polygons on a blank background. Accepted for a low-traffic demo.
- **Visitors' browsers fetch OSM tiles**, so OSM sees their IP; stated in `LICENSES.md`.
- **The demo goes stale between refreshes**, which the banner says; stale is honest, not wrong.
- **History rewrite is one-way for the public repo:** a mistake found after the push means deleting and recreating that repo (the private archive is the source of truth until then). Step 4's checks run before the push for that reason.
- **`areas_raw` is published** for 1,217 outages: VECO's own wording of the affected areas, linked to each post. Accepted as factual schedule data with attribution; whole posts are not published.
- **Wake timers depend on the power plan** and firmware; a laptop asleep in a bag won't wake (use `-NoWake`).
- **A PC that sleeps past the 6 h grace still misses a run**; the map's 15 h warning shows it.
- **The owner's name is in `LICENSE`** and commit author names; intended for a portfolio.
