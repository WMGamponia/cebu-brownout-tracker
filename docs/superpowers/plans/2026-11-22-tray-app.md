# Tray App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Windows tray icon that starts and supervises `serve`, shows whether the last run and publish went fine, notifies only when something needs the owner, and offers Run now, join-request approval, start at logon, and Quit.

**Architecture:** `serve` records each run's outcome in `meta`, writes a fresh admin token to `data/admin.token`, and adds token-guarded loopback routes (`/admin/*`) to the map app. A new `outages.tray` package does the rest. Its pure rules turn a status snapshot into an icon colour, menu lines and notification events. A supervisor starts, restarts or adopts `serve`. A thin `pystray` layer draws everything. The tray is the logon task, and `serve` runs as its hidden child.

**Tech Stack:** Python 3.12+, FastAPI (existing), httpx (existing), APScheduler 3 (existing), `pystray` + `Pillow` (new, optional extra `[tray]`), PowerShell `ScheduledTasks` cmdlets.

**Spec:** `docs/superpowers/specs/2026-11-22-tray-app-design.md`

## Global Constraints

- Windows 11; `python -m outages tray` exits with `error: the tray runs on Windows only` and code 2 elsewhere.
- `pystray` and `Pillow` only in `[project.optional-dependencies] tray`. Import them only inside `src/outages/tray/app.py`. No test imports them, and CI (Ubuntu + Windows) installs `.[dev]` only.
- `serve` without the tray behaves exactly as now, apart from the extra `meta` writes, the token file, and the loopback-only `/admin/*` routes.
- No console windows: every child process (serve, PowerShell, icacls) uses `subprocess.CREATE_NO_WINDOW`, as `publish.py` does.
- Run times stay `RUN_TIMES = ("06:00", "20:00")`. No new requests to VECO other than an owner-pressed Run now.
- Stale data threshold: `STALE_CHECK_H = 15` (existing). Missed-run slack: 10 min (`WATCHDOG_SLACK_MIN`, existing).
- Restart backoff 10 s, 60 s, 300 s. A 4th crash within 30 min stops restarts.
- Healthz grace: 60 s from process start before "not answering" turns red.
- Stop wait: up to 600 s for a run in progress, then kill the process tree. On sign-out/shutdown, 20 s.
- Status re-read every 30 s and right after every action.
- Commit messages: Conventional Commits, **no AI attribution lines** (owner rule).
- Work in the worktree `.claude/worktrees/tray-app` on `feat/tray-app`. Never switch the main checkout off `main`.

## Review Focus

1. **Fresh database or no new `meta` keys yet** (first run after upgrading): the tray must show grey or amber with "Last run: never", not crash and not show red. Test in Task 4 (`test_no_status_yet`).
2. **Unreadable or corrupt `data/tray_state.json`:** treat it as empty and overwrite it on the next save, without crashing. Test in Task 4 (`test_seen_corrupt_file`).
3. **Approve or Deny for a chat already decided in Telegram:** the route answers 404 `not pending`, nothing is sent to the user, and the menu refreshes. Test in Task 3 (`test_decide_not_pending`).
4. **Token changed under the tray** (serve restarted outside the tray): on a 403 the client re-reads `data/admin.token` once and retries. Test in Task 5 (`test_client_rereads_token_on_403`).
5. **Lock-held exit (code 3) of the tray's own child at start-up** (an orphaned serve is still alive): the supervisor adopts it and doesn't count it as a crash. Test in Task 5 (`test_exit_3_adopts_not_crash`).

### Task 2: Admin token and the `/admin/*` routes

**Files:**

- Modify: `src/outages/map/app.py` (`create_app` signature)

**Interfaces:**
- Produces:
  - `admintoken.TOKEN_FILE = "admin.token"`, `write_new(data_dir: Path) -> str` (32-byte `secrets.token_urlsafe`, written atomically, then on Windows `icacls <file> /inheritance:r /grant:r "%USERNAME%:F"` hidden; an icacls failure is logged, not raised), `read(data_dir: Path) -> str | None`.
  - `map.admin.AdminControl` (Protocol):
    - `run_now() -> bool` (False = a run is already in progress)
    - `pending() -> list[dict]` (`{"chat_id": int, "name": str | None, "requested_at": str}`)
    - `decide(chat_id: int, approve: bool) -> bool` (False = not pending)
    - `stop() -> None`
  - `map.admin.AdminConfig(token: str, control: AdminControl)` (dataclass)
  - `map.admin.HEADER = "X-Outages-Admin"`

- Routes:
  - `POST /admin/run` → 202 `{"started": true}` or 409 `{"error": "already running"}`
  - `GET /admin/pending` → 200 `{"pending": [...]}`

### Task 4: Tray rules (pure) and the notified-events store

**Files:**
- Create: `src/outages/tray/__init__.py`, `src/outages/tray/state.py`, `src/outages/tray/seen.py`
- Test: `tests/test_tray_state.py`, `tests/test_tray_seen.py`

**Interfaces:**
- Consumes: `RunStatus` (Task 1); `scheduler.missed_slot`, `scheduler.latest_slot`; `STALE_CHECK_H`.
- Produces:
  - `ProcState = Literal["starting", "running", "restarting", "stopped", "capped", "adopted"]`
  - `@dataclass(frozen=True) class Snapshot: now: datetime; proc: ProcState; proc_since: datetime; healthz_ok: bool; status: RunStatus; pending: list[dict]; crashed_at: datetime | None` (the last crash restarted).
  - `Colour = Literal["green", "amber", "red", "grey"]`
  - `@dataclass(frozen=True) class Event: key: str; text: str`
  - `@dataclass(frozen=True) class View: colour: Colour; headline: str; lines: list[str]; tooltip: str; events: list[Event]; can_act: bool`
  - `evaluate(s: Snapshot) -> View`
- Rules (worst wins; reasons collected in this order):
  - **Red:**
    - `proc == "capped"` → reason `crash_cap`, "serve keeps crashing; restarts stopped".
    - `status.last_check_ok is False` → `check_failed`, "Check failed".
    - `publish_status in ("failed", "skipped")` → `publish_<status>`, "Publish skipped: <detail>" / "Publish failed: <detail>".
    - `proc in ("running", "adopted")` and not `healthz_ok` and `now - proc_since >= 60 s` → `not_answering`, "serve is running but not answering (map port in use?)".
  - **Grey:** `proc == "stopped"`, or `proc == "starting"` and under 60 s.
  - **Amber:**
    - `missed_slot(last_run_at, now)` is not None → `missed`, "Missed the HH:MM run".
    - `last_check_at` older than `STALE_CHECK_H`, or None while the process has been up > 60 s → `stale`.
    - `proc == "restarting"`.
  - **Green:** otherwise.
- Event keys (one per (reason, run)):
  - `f"{reason}:{iso(last_run_at)}"` for `check_failed` / `publish_*`
  - `f"missed:{iso(slot)}"`
  - `f"crash:{iso(crashed_at)}"` (text "serve crashed and was restarted")
  - `f"crash_cap:{iso(proc_since)}"`
  - `f"not_answering:{iso(proc_since)}"`
  - `f"join:{chat_id}"` (text "Join request from <name or chat id>: right-click to approve")
  - No events for green, grey, stale or restarting.
- `lines`:
  - `"Last run: Sun 22 Nov 20:00 · OK"` (Manila time; `· check failed` when not OK; `"Last run: never"` when None)
  - `"Publish: published abc1234"` / `"Publish: skipped: not on main"` / `"Publish: off"` / `"Publish: none yet"`
  - `"Next run: Mon 23 Nov 06:00"`
  - `"serve: started elsewhere"` only when adopted
- `tooltip`: `"Last run 20:00 OK · published abc1234 · next 06:00"`, cut to 127 chars (the Windows limit).
- `can_act = healthz_ok`.
- `seen.Seen(path: Path)`, with `.load()` (a missing or corrupt file → empty) and `.fresh(events: list[Event]) -> list[Event]`. `fresh` returns the unseen ones, marks them, and saves atomically. The newest 500 keys are kept.

### Task 5: Supervisor and serve client

**Files:**
- Create: `src/outages/tray/supervisor.py`, `src/outages/tray/client.py`
- Test: `tests/test_tray_supervisor.py`, `tests/test_tray_client.py`

**Interfaces:**
- Consumes: `ProcState` (Task 4); `admintoken.read` (Task 2); `LOCK_NAME`, exit code 3 from `outages.__main__` (an existing contract: `main` returns 3 when the lock is held).
- Produces:
  - `class Proc(Protocol)`: `pid: int`, `poll() -> int | None`, `kill_tree() -> None`.
  - `spawn_serve(root: Path) -> Proc`: `[sys.executable with python.exe → pythonw.exe, "-m", "outages", "serve"]`, `cwd=root`, `creationflags=CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP`, stdio to DEVNULL. `kill_tree` runs `taskkill /T /F /PID` hidden.
  - `lock_held(data_dir: Path) -> bool`: try `lock.acquire(data_dir / LOCK_NAME)` and release it at once.
  - `class Supervisor`, constructed with:
    - `spawn: Callable[[], Proc]`
    - `lock_held: Callable[[], bool]`
    - `clock: Callable[[], datetime]`
    - `backoff=(10, 60, 300)`
    - `cap_window=timedelta(minutes=30)`
    - `cap_count=4`
  - `Supervisor` methods:
    - `start()`: if `lock_held()`, become `adopted`; else spawn and become `starting`.
    - `tick() -> None`, called every poll. It handles:
      - an exit code 3 → `adopted`;
      - any other unexpected exit → record a crash, then `restarting` until the backoff passes, then spawn; at the 4th crash within the window → `capped`;
      - in `adopted`, a free lock → spawn → `starting`.
    - `mark_healthy()`: `starting` → `running`.
    - `stop(request_stop: Callable[[], bool], timeout_s: float)`: calls `request_stop()` (the HTTP stop), then polls until the process exits or the timeout passes, then `kill_tree`. Adopted: wait for the lock to free, else `taskkill` the PID read from the lock file. Ends in `stopped`.
    - `restart_now()`: resets the crash history, then `stop` + `start`.
    - Properties `state: ProcState`, `since: datetime`, `last_crash: datetime | None`.
  - `class ServeClient(base_url="http://127.0.0.1:8765", data_dir: Path, transport=None)` (httpx, 5 s timeout):
    - `healthz() -> bool`
    - `run_now() -> Literal["started", "busy", "error"]`
    - `pending() -> list[dict]` (`[]` on error)
    - `decide(chat_id, approve) -> Literal["ok", "not_pending", "error"]`
    - `stop() -> bool`
    - Every admin call sends `HEADER` with `admintoken.read`; on a 403 it re-reads the token once and retries. It never sends `Origin`.
