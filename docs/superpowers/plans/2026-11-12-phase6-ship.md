# Phase 6 Ship It Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the tracker: an offline `snapshot` command and snapshot-aware pages for a GitHub Pages demo, a visitor-first README, start-at-login with a single-instance lock, and a rewritten history pushed to a new public repo.

**Architecture:** The existing pages gain one pure data-source module (`source.js`) that maps every data URL and every "now" to either the live server or a static snapshot folder; `<html data-mode>` picks the mode. `outages/snapshot.py` builds every document in memory with the server's own `build()` / `compute()` / `dumps()` on a read-only connection guarded by a SQLite authorizer, scans the bytes for secrets, then writes the folder. `outages/lock.py` holds an OS lock for the commands that write or send. The history rewrite runs once, in a scratch clone, with `git filter-repo` and the committed fixture trimmer.

**Tech Stack:** Python 3.12+ (dev 3.14), stdlib `sqlite3`, `msvcrt`/`fcntl`, `shutil`; FastAPI (unchanged); Leaflet 1.9.4 vendored; Node 22+ `node:test`; PowerShell 5.1 ScheduledTasks module; `git-filter-repo` (one-off, not a dependency). pytest, ruff, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-12-phase6-ship-design.md` (read it first; § numbers below refer to it). Phase 4 spec §4.3 for the map document, Phase 5 spec §4.8 for stats.

## Review Focus

1. **The snapshot week is shorter than 7 days** (VECO's last stored end is 2 days away) or empty (no future outage: `Window(today, today)`): the picker still steps to the previous full week and back, and the date input snaps a date inside the short week to it → Task 3 `snapWeek` tests with a 2-day snapshot week, Task 4 `test_windows_tile_with_short_snapshot_week`.
2. **A visitor opens an old link** `…/?from=2024-02-01&days=7` or `history?from=…&to=…` on the snapshot (copied from the local map): the page ignores the live parameters and shows the snapshot week / the default range instead of a 404 banner → Task 3 `test_snapshot_ignores_live_params`.
3. **A chat ID that is a substring of an unrelated number** (a 9-digit chat ID inside a 10-digit coordinate string or another ID): the scan must match whole digit runs only, so `12345678` doesn't fire on `123456789`, but does fire on `"chat":12345678,` → Task 4 `test_leak_scan_matches_whole_numbers_only`.
4. **`--out site` where `site/` is the `gh-pages` worktree after a refresh that drops a week** (oldest week falls off): the dropped file is deleted, `.git` (a file) survives, unknown files the owner added are refused, not deleted → Task 4 `test_refresh_removes_dropped_week_keeps_git_file`, `test_foreign_file_refused`.
5. **`serve` started twice from Task Scheduler and a terminal, where the first holder crashed** and left `serve.lock` with its PID: the new start must succeed (OS lock gone), and a live holder's PID must be readable for the message on Windows (where locked bytes can't be read) → Task 1 `test_stale_lock_file_does_not_block`, `test_held_lock_reports_pid`.
